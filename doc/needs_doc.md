## 用户端
### 点餐外卖页面
登录、商品浏览、详细信息、增删购物车、下单、支付、催单、查看历史订单、地址管理、搜索
### 饮食健康分析页面
提取食物信息添加至每日饮食、智能分析饮食健康程度、提出餐饮优化意见、根据意见提供推荐的菜品分类、单独记录饮食

## 商家端
### 商家管理页面
登录、商品管理、订单管理、来单提示、催单提示、商家信息管理、数据分析、优惠活动管理、菜品标签（便于提取食物信息用于分析、搜索）

## 详细设计：

认证设计：用户端和商家端均使用账号密码登录。密码仅保存不可逆哈希值；登录成功后服务端签发 JWT，客户端在后续请求的 `Authorization: Bearer <token>` 请求头中携带。JWT 至少包含用户 id 和用户角色；服务端校验签名、有效期和用户状态后完成鉴权。JWT 为无状态凭证，不保存到用户表；退出登录由客户端清除令牌。用户角色至少包含普通用户和商家用户。
用户表：Id、密码哈希、姓名、性别、电话、头像路径、创建时间、修改时间、用户角色。电话需要建立唯一索引。
商家表：记录商家信息。包含：商家 id、商家名称、头像路径、商家介绍、商家地址、联系电话、营业时间、营业状态、用户 id（商家）
菜品表：记录所有菜品。包含：菜品 id、商家 id、分类 id、餐品名称、价格、描述、图片路径、销售量、菜品状态（上架、下架、售罄、删除）、菜品具体营养成分（选填）。
        备注：每个商家每种菜品只能存在一个，所以需要建立唯一索引，建立(merchant_id, dish_name)唯一索引，同时由于方便菜品状态的修改而不用修改索引，所以添加菜品状态列，
             通过软删除方式标记每个菜品的状态。要给商家 id 建立索引方便查找
菜品分类表：记录所有菜品对应的分类，方便与 分类-营养表 对应。包含：分类 id、分类名称、初始排序（通过数值形式说明这些菜品的排序）
分类-营养表：记录每种分类对应的营养成分标签，方便通过标签来判断摄入营养。包含：id、分类 id、营养成分标签（高蛋白、高脂肪等）
套餐表：记录每个商家的套餐。包含：套餐 id、商家 id、套餐名称、套餐价格、套餐描述、套餐图片路径、套餐状态、销售量
套餐菜品表：记录每个套餐里的菜品。包含：id、套餐 id、菜品 id、菜品份数
订单表：记录每个用户的订单。包含：订单 id、用户 id、商家 id、订单状态、下单时间、支付时间、总金额、收货地址快照、收货人电话、实付金额快照
订单明细表：记录每个订单详细信息。包含：id、订单 id、商品 id、商品类型、商品名称快照、商品价格快照、商品份数
用户地址表：记录用户的送餐地址。包含：id、用户 id、地址、联系电话、是否启用、备注
购物车表：记录用户添加到购物车的菜品。包含：id、用户 id、商家 id、商品类型（套餐 or 单独菜品）、商品 id、数量、是否勾选去结账
饮食记录表：记录用户的饮食情况。包含：id、用户 id、菜品 id（可以为空）、用户填写食品名称（可以为空）、用户填写食品营养标签（可以为空）、用餐时间、用餐数量
营养记录表：记录用户饮食营养信息。包含：id、用户 id、分类 id、营养成分标签、日期
饮食健康分析表：用于 Agent 根据营养记录表分析得到建议、评分等。包含：id、用户 id、分析创建日期、健康评分、风险摘要、优化建议、分析模型
饮食推荐表：用于根据饮食健康分析对用户给出饮食推荐。包含：id、用户 id、饮食健康分析表 id、推荐菜品分类 id、推荐分数、推荐原因、创建时间

短期范围说明：优惠活动管理仅作为后续功能预留，本期不支持优惠规则配置和订单优惠结算；支付可使用模拟支付，不接入第三方支付渠道。
