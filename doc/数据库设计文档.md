# 数据库设计文档

## 1. 范围与约定

本文仅以 `needs_doc.md` 为依据，面向短期可交付版本。优惠活动不参与本期订单结算，支付使用模拟支付，不建立支付流水表。

- 数据库建议使用 MySQL 8.0，主键使用 `bigint` 自增或雪花 ID。
- 金额使用 `decimal(10,2)`；数量使用 `int` 或 `decimal(10,2)`（允许半份等场景时使用后者）。
- 除明确说明外，关联字段为逻辑外键；服务层必须校验关联记录存在且状态可用。
- 所有时间使用 `datetime`。`create_time`、`update_time` 分别表示创建和最后修改时间。
- 图片、头像等资源字段存储文件访问路径，不直接存储文件二进制。

## 2. 登录与权限

账号信息统一存储在 `user` 表。密码字段只保存密码哈希，不能保存明文密码。登录成功后服务端签发 JWT，令牌不落库，也不在表中设置“登录凭证”字段。

JWT 至少携带 `user_id` 和 `role` 两项声明；客户端通过 `Authorization: Bearer <token>` 传递。接口校验签名、过期时间和用户状态。`role` 为 `USER`（普通用户）或 `MERCHANT`（商家用户）；商家用户仅能操作 `merchant.user_id` 指向自己的商家数据。

## 3. 表清单

| 表名 | 用途 |
| --- | --- |
| `user` | 用户与商家登录账号 |
| `merchant` | 商家资料与归属账号 |
| `dish_category` | 平台统一菜品分类 |
| `category_nutrition` | 分类对应的营养标签 |
| `dish` | 单品菜品 |
| `setmeal` | 商家套餐 |
| `setmeal_dish` | 套餐和菜品的组成关系 |
| `user_address` | 用户收货地址 |
| `shopping_cart` | 用户购物车商品 |
| `orders` | 订单主信息和下单快照 |
| `order_detail` | 订单商品快照 |
| `diet_record` | 用户单次饮食记录 |
| `nutrition_record` | 用户按日聚合的营养标签记录 |
| `health_analysis` | Agent 健康分析结果 |
| `diet_recommendation` | 基于分析结果的分类推荐 |

## 4. 表结构

### 4.1 `user` 用户表

| 字段 | 类型 | 约束/说明 |
| --- | --- | --- |
| id | bigint | 主键 |
| password_hash | varchar(255) | 密码哈希，非空 |
| name | varchar(64) | 用户姓名 |
| gender | varchar(16) | 可空，例如 MALE、FEMALE、UNKNOWN |
| phone | varchar(32) | 非空，唯一索引；同时作为登录账号 |
| avatar_path | varchar(255) | 可空 |
| role | varchar(16) | 非空：`USER`、`MERCHANT` |
| status | tinyint | 非空，1 正常、0 禁用；JWT 校验时检查 |
| create_time | datetime | 非空 |
| update_time | datetime | 非空 |

索引：`uk_user_phone(phone)`、`idx_user_role(role)`。

### 4.2 `merchant` 商家表

| 字段 | 类型 | 约束/说明 |
| --- | --- | --- |
| id | bigint | 主键 |
| user_id | bigint | 非空，商家管理员账号；唯一索引 |
| name | varchar(128) | 非空，商家名称 |
| avatar_path | varchar(255) | 可空 |
| description | varchar(500) | 可空 |
| address | varchar(255) | 非空 |
| phone | varchar(32) | 非空 |
| business_hours | varchar(128) | 可空，例如 09:00-21:00 |
| business_status | tinyint | 非空，1 营业、0 停业 |
| create_time | datetime | 非空 |
| update_time | datetime | 非空 |

索引：`uk_merchant_user_id(user_id)`、`idx_merchant_status(business_status)`。

### 4.3 `dish_category` 菜品分类表

分类是平台统一的健康与浏览分类，不属于某一商家。

| 字段 | 类型 | 约束/说明 |
| --- | --- | --- |
| id | bigint | 主键 |
| name | varchar(64) | 非空，唯一 |
| initial_sort | int | 非空，默认 0；数值小的靠前 |
| create_time | datetime | 非空 |
| update_time | datetime | 非空 |

索引：`uk_dish_category_name(name)`、`idx_dish_category_sort(initial_sort)`。

### 4.4 `category_nutrition` 分类-营养表

保存分类的定性营养标签，例如“高蛋白”“高脂肪”。该表不保存热量等精确营养数值。

| 字段 | 类型 | 约束/说明 |
| --- | --- | --- |
| id | bigint | 主键 |
| category_id | bigint | 非空，关联 `dish_category.id` |
| nutrition_tag | varchar(64) | 非空 |
| create_time | datetime | 非空 |

索引：`uk_category_nutrition(category_id, nutrition_tag)`、`idx_category_nutrition_tag(nutrition_tag)`。

### 4.5 `dish` 菜品表

`nutrition_detail` 保存商家可选录入的具体营养说明；短期版本可使用 JSON 文本，例如 `{\"calories\":320,\"protein_g\":22}`，未录入时健康分析回退到分类标签。

| 字段 | 类型 | 约束/说明 |
| --- | --- | --- |
| id | bigint | 主键 |
| merchant_id | bigint | 非空，关联 `merchant.id` |
| category_id | bigint | 非空，关联 `dish_category.id` |
| name | varchar(128) | 非空，菜品名称 |
| price | decimal(10,2) | 非空，价格大于等于 0 |
| description | varchar(1000) | 可空 |
| image_path | varchar(255) | 可空 |
| sales_count | int | 非空，默认 0 |
| status | varchar(16) | 非空：`ON_SALE`、`OFF_SALE`、`SOLD_OUT`、`DELETED` |
| nutrition_detail | json | 可空，具体营养成分 |
| create_time | datetime | 非空 |
| update_time | datetime | 非空 |

索引：`uk_dish_merchant_name(merchant_id, name)`、`idx_dish_merchant_status(merchant_id, status)`、`idx_dish_category(category_id)`。

说明：该唯一索引意味着软删除后不能新建同商家的同名菜品；短期版本按此规则处理，删除菜品可改为重新上架原记录。

### 4.6 `setmeal` 套餐表

| 字段 | 类型 | 约束/说明 |
| --- | --- | --- |
| id | bigint | 主键 |
| merchant_id | bigint | 非空，关联 `merchant.id` |
| name | varchar(128) | 非空 |
| price | decimal(10,2) | 非空，价格大于等于 0 |
| description | varchar(1000) | 可空 |
| image_path | varchar(255) | 可空 |
| status | varchar(16) | 非空：`ON_SALE`、`OFF_SALE`、`SOLD_OUT`、`DELETED` |
| sales_count | int | 非空，默认 0 |
| create_time | datetime | 非空 |
| update_time | datetime | 非空 |

索引：`uk_setmeal_merchant_name(merchant_id, name)`、`idx_setmeal_merchant_status(merchant_id, status)`。

### 4.7 `setmeal_dish` 套餐菜品表

| 字段 | 类型 | 约束/说明 |
| --- | --- | --- |
| id | bigint | 主键 |
| setmeal_id | bigint | 非空，关联 `setmeal.id` |
| dish_id | bigint | 非空，关联 `dish.id`；必须属于同一商家 |
| copies | decimal(10,2) | 非空，大于 0，菜品份数 |
| create_time | datetime | 非空 |

索引：`uk_setmeal_dish(setmeal_id, dish_id)`、`idx_setmeal_dish_dish(dish_id)`。

### 4.8 `user_address` 用户地址表

| 字段 | 类型 | 约束/说明 |
| --- | --- | --- |
| id | bigint | 主键 |
| user_id | bigint | 非空，关联 `user.id` |
| address | varchar(255) | 非空 |
| contact_phone | varchar(32) | 非空 |

| create_time | datetime | 非空 |
| update_time | datetime | 非空 |

索引：`idx_user_address_user_enabled(user_id, enabled)`。

### 4.9 `shopping_cart` 购物车表

`product_type` 与 `product_id` 组成多态关联：`DISH` 对应 `dish.id`，`SETMEAL` 对应 `setmeal.id`。写入和结算时必须验证商品归属 `merchant_id`。

| 字段 | 类型 | 约束/说明 |
| --- | --- | --- |
| id | bigint | 主键 |
| user_id | bigint | 非空，关联 `user.id` |
| merchant_id | bigint | 非空，关联 `merchant.id` |
| product_type | varchar(16) | 非空：`DISH`、`SETMEAL` |
| product_id | bigint | 非空 |
| quantity | int | 非空，大于 0 |
| selected | tinyint | 非空，1 已勾选、0 未勾选 |
| create_time | datetime | 非空 |
| update_time | datetime | 非空 |

索引：`uk_cart_item(user_id, merchant_id, product_type, product_id)`、`idx_cart_user_merchant(user_id, merchant_id)`。

一次结算只能选择同一商家的购物车条目，并生成一张订单。

### 4.10 `orders` 订单表

订单金额与收货信息均为订单创建时的快照，不能在读取历史订单时回查可变的地址或商品价格。

| 字段 | 类型 | 约束/说明 |
| --- | --- | --- |
| id | bigint | 主键 |
| order_no | varchar(64) | 非空，唯一订单号 |
| user_id | bigint | 非空，关联 `user.id` |
| merchant_id | bigint | 非空，关联 `merchant.id` |
| status | varchar(20) | 非空：`PENDING_PAYMENT`、`PENDING_ACCEPT`、`PREPARING`、`DELIVERING`、`COMPLETED`、`CANCELLED` |
| order_time | datetime | 非空 |
| payment_time | datetime | 可空；模拟支付成功时写入 |
| total_amount | decimal(10,2) | 非空，商品合计 |
| paid_amount | decimal(10,2) | 非空，实付金额；本期等于商品合计 |
| delivery_address_snapshot | varchar(255) | 非空 |
| recipient_phone_snapshot | varchar(32) | 非空 |
| reminder_count | int | 非空，默认 0 |
| last_reminder_time | datetime | 可空 |
| create_time | datetime | 非空 |
| update_time | datetime | 非空 |

索引：`uk_orders_order_no(order_no)`、`idx_orders_user_time(user_id, order_time)`、`idx_orders_merchant_status_time(merchant_id, status, order_time)`。

催单仅允许在 `PENDING_ACCEPT` 或 `PREPARING` 状态下进行；前后端需设定冷却时间，避免重复提醒。

### 4.11 `order_detail` 订单明细表

| 字段 | 类型 | 约束/说明 |
| --- | --- | --- |
| id | bigint | 主键 |
| order_id | bigint | 非空，关联 `orders.id` |
| product_id | bigint | 非空，原商品 ID |
| product_type | varchar(16) | 非空：`DISH`、`SETMEAL` |
| product_name_snapshot | varchar(128) | 非空 |
| product_price_snapshot | decimal(10,2) | 非空，购买时单价 |
| quantity | int | 非空，大于 0 |
| create_time | datetime | 非空 |

索引：`idx_order_detail_order(order_id)`。

### 4.12 `diet_record` 饮食记录表

一条记录对应一次用餐中的一个食物来源。系统菜品与手工食物必须二选一：`dish_id` 非空时手填字段应为空；`dish_id` 为空时 `food_name` 必填。

| 字段 | 类型 | 约束/说明 |
| --- | --- | --- |
| id | bigint | 主键 |
| user_id | bigint | 非空，关联 `user.id` |
| dish_id | bigint | 可空，关联 `dish.id` |
| food_name | varchar(128) | 可空，手工食品名称 |
| food_nutrition_tags | json | 可空，手工食品的标签数组 |
| meal_time | datetime | 非空 |
| quantity | decimal(10,2) | 非空，大于 0 |
| create_time | datetime | 非空 |
| update_time | datetime | 非空 |

索引：`idx_diet_record_user_meal_time(user_id, meal_time)`、`idx_diet_record_dish(dish_id)`。

### 4.13 `nutrition_record` 营养记录表

该表按用户、日期和营养标签聚合，由饮食记录生成，用于高效进行日维度健康分析。

| 字段 | 类型 | 约束/说明 |
| --- | --- | --- |
| id | bigint | 主键 |
| user_id | bigint | 非空，关联 `user.id` |
| category_id | bigint | 可空，关联 `dish_category.id`；手工食品可为空 |
| nutrition_tag | varchar(64) | 非空 |
| record_date | date | 非空 |
| create_time | datetime | 非空 |
| update_time | datetime | 非空 |

索引：`idx_nutrition_record_user_date(user_id, record_date)`、`idx_nutrition_record_user_date_tag(user_id, record_date, nutrition_tag)`。

### 4.14 `health_analysis` 饮食健康分析表

| 字段 | 类型 | 约束/说明 |
| --- | --- | --- |
| id | bigint | 主键 |
| user_id | bigint | 非空，关联 `user.id` |
| analysis_date | date | 非空，分析覆盖日期 |
| input_revision | bigint | 非空，本次分析使用的用户当日营养输入版本 |
| health_score | decimal(5,2) | 非空，建议范围 0 至 100 |
| risk_summary | varchar(1000) | 可空 |
| optimization_suggestion | text | 可空 |
| analysis_model | varchar(128) | 非空，Agent/规则版本标识 |
| create_time | datetime | 非空 |

索引：`idx_health_analysis_user_date(user_id, analysis_date)`、`idx_health_analysis_user_date_revision(user_id, analysis_date, input_revision)`。

`input_revision` 从对应的 `health_analysis_task.input_revision` 复制而来。查询结果时可将其与用户该日期的当前营养输入版本比较，以判断分析是否仍基于最新饮食数据；历史结果不能因后续饮食变化而修改该字段。

### 4.15 `diet_recommendation` 饮食推荐表

推荐仅指向菜品分类；前端依据分类实时查询营业商家的在售菜品。

| 字段 | 类型 | 约束/说明 |
| --- | --- | --- |
| id | bigint | 主键 |
| user_id | bigint | 非空，关联 `user.id` |
| health_analysis_id | bigint | 非空，关联 `health_analysis.id` |
| recommended_category_id | bigint | 非空，关联 `dish_category.id` |
| recommendation_score | decimal(5,2) | 非空 |
| reason | varchar(1000) | 可空 |
| create_time | datetime | 非空 |

索引：`idx_diet_recommendation_analysis_score(health_analysis_id, recommendation_score)`、`idx_diet_recommendation_user(user_id)`。

## 5. 关键业务规则

1. 商家用户必须且只能管理其 `merchant.user_id` 对应的商家、菜品、套餐和订单。
2. 下单时仅允许购买营业中商家的 `ON_SALE` 商品；订单创建后，必须写入订单与订单明细快照，再清理已结算的购物车条目。
3. 模拟支付仅将订单从 `PENDING_PAYMENT` 更新为 `PENDING_ACCEPT`，并写入 `payment_time`；商家接单后按既定状态流转。
4. 套餐的营养分析在短期版本中按其 `setmeal_dish` 所含菜品及份数推导；用户手工新增饮食则依据填写的标签参与定性分析。
5. 菜品状态为 `DELETED` 的记录不对用户端展示、不允许加入购物车，也不得修改既有订单和饮食记录中的历史引用。
